# Скринер S&P 500 с бумажной торговлей и отчётом в Excel

Автономный робот, который каждый торговый день сам, без вашего участия,
просматривает весь индекс S&P 500, отбирает лучшую по коэффициентам акцию,
покупает её на виртуальные деньги и держит месяц. Работает на бесплатных
GitHub Actions, состояние портфеля хранит в самом репозитории, а результат
кладёт в готовый файл `Portfolio.xlsx`.

Раз в месяц робот сам пересматривает веса факторов: смотрит, какие группы
показателей действительно предсказывали доходность, и осторожно сдвигает веса
в их сторону — с проверкой на независимом отрезке и откатом, если стало хуже.

**Это бумажная торговля.** Ни к какому брокеру ничего не подключено, реальные
деньги не двигаются, ордера никуда не отправляются. Это исследовательский
инструмент, а не инвестиционная рекомендация.

---

## Как это торгует

Стратегия — «лестница» (ladder):

| Параметр | Значение |
|---|---|
| Стартовый капитал | $10 000 виртуальных |
| Покупок в день | 1 |
| Срок удержания | 21 торговый день (≈ месяц) |
| Одновременных позиций | до 21 |
| Размер позиции | капитал / 21 (доходность реинвестируется) |
| Дубли тикеров | запрещены |
| Лимит на сектор | не более 7 позиций из 21 |
| Проскальзывание | 5 б.п. в каждую сторону |
| Комиссия | $0 |

В установившемся режиме лестница заполнена: каждый день одна позиция
закрывается по сроку и одна новая открывается. Это и даёт те самые ~250
сделок в год.

**Важная деталь про исполнение.** Сигнал считается по цене закрытия дня T,
а сделка исполняется по цене **открытия дня T+1**. Робот физически не может
купить по той же цене, которую использовал для решения. Без этого правила
любой бэктест показывает красивую, но недостижимую доходность.

## Откуда берутся данные

Здесь главный компромисс всего проекта: нужно ежедневно оценивать ~500 бумаг,
имея бесплатные лимиты. Решение — разделить данные по частоте изменения.

**Ежедневно — только цены.** Один пакетный запрос через `yfinance` на всю
вселенную сразу (сотни тикеров за несколько HTTP-вызовов, ключ не нужен).
Из цен считаются RSI, моментум, скользящие средние и текущая стоимость
позиций. Резерв — Stooq, затем локальный кэш: если провайдер лежит, робот
работает на последних известных данных, а не падает.

**Раз в неделю — фундаментал.** P/E, ROE, маржа и прочее меняются только по
квартальным отчётам, поэтому опрашивать 500 тикеров каждый день бессмысленно
и это основной способ получить бан. Воскресный запуск добавляет **новый
снимок с датой `asof`**, а не перезаписывает старый. Накопленная история
позволяет читать фундаментал point-in-time — таким, каким он был известен на
день решения, а не подставлять сегодняшние цифры в прошлогодние сделки.

**Alpha Vantage — только на подтверждение.** Ключ тратится на проверку 1–3
финальных кандидатов дня: сходится ли цена с нашей, не разошлись ли P/E и P/B
с кэшем, не делистинг ли. Это 1–3 запроса в день против лимита 25. Расход
считается в файле `state/cache/av_usage.json`. Если AV недоступен — вердикт
`unverified`, и робот спокойно продолжает.

## Как отбираются акции

Сначала жёсткие фильтры: цена > $5, средний дневной оборот > $5 млн,
капитализация > $2 млрд, не меньше 200 дней истории, не больше 3 пропущенных
коэффициентов. У каждой отброшенной бумаги в отчёте есть человекочитаемая
причина.

Дальше — кросс-секционный скоринг. Оценка **относительная**: бумага
сравнивается с остальными участниками индекса на ту же дату, а не с
абсолютными порогами. Поэтому лучший кандидат находится в любой фазе рынка.

Для каждого показателя: отсекаются бессмысленные значения (отрицательный P/E —
это не «дёшево», а отсутствие прибыли), обрезаются по 2% хвосты, считается
z-оценка по срезу, знак переворачивается для показателей «чем меньше, тем
лучше». Оценка блока — среднее его z-оценок, итоговая — взвешенная сумма
блоков.

| Блок | Вес по умолчанию | Показатели |
|---|---|---|
| Value | 0.30 | P/E, P/B, EV/EBITDA, P/S, FCF yield |
| Quality | 0.25 | ROE, gross margin, net margin, net debt/EBITDA |
| Growth | 0.15 | рост выручки, рост прибыли |
| Momentum | 0.30 | 3м, 6м, 12м-без-последнего-месяца, выше MA200, RSI |

Если у бумаги нет целого блока данных, веса **пересчитываются** по доступным
блокам, а не проставляется ноль — иначе робот наказывал бы компании просто за
пробел у провайдера.

## Самообучение

Раз в месяц (`monthly`):

1. Восстанавливается история: какие оценки робот выставил бы на прошлые даты,
   используя только те данные, что были известны тогда.
2. Для каждого блока считается **information coefficient** — ранговая
   корреляция Спирмена его оценок с фактической доходностью за следующие 21
   день.
3. Предлагаются новые веса пропорционально положительным IC.
4. Предложение проверяется на отложенном отрезке, которого не было в обучении.
5. Если стало хуже — **откат**, и причина пишется в лог.

Защита от переобучения намеренно многослойная: вес не может выйти за
[0.05, 0.50], сдвиг не больше 0.05 за месяц, обучение не запускается пока нет
40 закрытых сделок, вклад фундаментальных блоков урезается при слабом покрытии
данными. Каждое решение — строка в `state/weights_history.csv`, а изменение
весов видно в диффе `config.yml`. Любой месяц можно откатить обычным
`git revert`.

Режимы в `config.yml`: `auto_bounded` (менять само), `propose_pr` (только
предлагать), `off`.

## Развёртывание: пошагово

### 1. Перевыпустите ключ Alpha Vantage

Ключ, который вы присылали в переписке, считайте скомпрометированным —
он побывал в чате. Получите новый на
[alphavantage.co/support/#api-key](https://www.alphavantage.co/support/#api-key)
и больше никому его не показывайте. В коде ключ нигде не хранится: он читается
только из переменной окружения `ALPHAVANTAGE_KEY`.

### 2. Залейте проект на GitHub

Git в командной строке для этого не нужен. Проще всего через
[GitHub Desktop](https://desktop.github.com/) — git в него уже встроен,
отдельно ставить нечего, токены не нужны, вход через браузер:

1. `File` → `Add local repository` → укажите папку с проектом.
2. Программа скажет, что это ещё не репозиторий, и предложит `create a
   repository` — согласитесь. В открывшемся окне `Git ignore` и `License`
   оставьте **None**: свой `.gitignore` в проекте уже есть, и шаблонный его
   перезапишет.
3. Слева появится список ~28 изменённых файлов. Внизу впишите описание
   (например «начальная версия скринера») и нажмите `Commit to main`.
4. Сверху появится кнопка `Publish repository`. Галочку `Keep this code
   private` можно оставить — расписания работают и в приватных репозиториях.

Пустой репозиторий на сайте заранее создавать не нужно: `Publish` создаст его
сам.

Про лимиты: у бесплатного аккаунта приватные репозитории получают 2000 минут
Actions в месяц. Этот робот расходует примерно 250–350 — с большим запасом.
У публичных репозиториев минуты не ограничены вовсе, но тогда ваш портфель
видят все; выбор за вами, реальных денег он всё равно не касается.


Обычный пароль GitHub больше не принимает. При `push` либо откроется браузер
для входа, либо спросят логин и пароль — и в поле пароля нужен **Personal
Access Token** (`Settings` → `Developer settings` → `Personal access tokens` →
`Tokens (classic)` → `Generate new token`, право `repo`).

### 3. Добавьте секрет

`Settings` → `Secrets and variables` → `Actions` → `New repository secret`

| Поле | Значение |
|---|---|
| Name | `ALPHAVANTAGE_KEY` |
| Secret | ваш новый ключ |

### 4. Разрешите Actions писать в репозиторий

`Settings` → `Actions` → `General` → внизу `Workflow permissions` →
**Read and write permissions** → `Save`.

Без этого робот не сможет закоммитить состояние портфеля, и каждый запуск
будет начинаться с нуля.

### 5. Наберите фундаментал

`Actions` → `weekly-fundamentals` → `Run workflow`. Первый запуск идёт долго
(порядка получаса на 500 тикеров — это последовательные запросы, такова
природа источника). Без него первые скрины пойдут только по ценовым факторам.

### 6. Запустите первый торговый день

`Actions` → `daily` → `Run workflow`. Дальше расписание работает само:

| Воркфлоу | Когда | Что делает |
|---|---|---|
| `daily` | Пн–Пт, 22:15 UTC | скрин, сделка, отчёт, коммит |
| `weekly-fundamentals` | Вс, 06:00 UTC | обновление коэффициентов |
| `monthly-learning` | 1-го числа, 07:00 UTC | подстройка весов |
| `tests` | на каждый push | прогон тестов |

Cron в GitHub Actions всегда в UTC, так что при переходе США на летнее время
локальный час съезжает. Это не важно: 22:15 UTC остаётся заведомо после
закрытия рынка (16:00 ET).

### 7. Смотрите результат

После каждого запуска в корне репозитория обновляется `Portfolio.xlsx` —
можно открыть прямо на GitHub или скачать из артефактов запуска.

## Что вы увидите в Excel

Восемь листов:

**Сводка** — капитал, доходность, сравнение с SPY, максимальная просадка,
Sharpe, доля прибыльных сделок, график кривой капитала и структура по
секторам.

**Позиции** — открытые позиции с живыми формулами. Колонка «Тек. цена»
подсвечена и предназначена для ручного ввода: впишите свою цену, и переоценка,
доходность и остаток срока пересчитаются сами.

**Сделки** — журнал всех закрытых сделок: вход, выход, P&L, сколько держали,
причина выхода, вердикт Alpha Vantage.

**Капитал** — дневная кривая капитала против бенчмарка.

**Скрин** — топ-60 сегодняшнего рейтинга с оценками по блокам и причинами
отсева.

**Факторы** — текущие веса и история их изменений роботом.

**Инфо** — режим работы, расход квоты API и оговорки.

**_данные** — скрытый лист с историей цен для спарклайнов.

## Локальный запуск

```bash
pip install -r requirements.txt

python -m screener weekly          # набрать фундаментал (долго)
python -m screener daily           # один торговый день
python -m screener daily --offline # то же, но на кэше, без сети
python -m screener monthly --dry-run  # оценить веса, ничего не меняя
python -m screener report          # пересобрать Excel из текущего состояния

python tests/test_screener.py      # 20 тестов
python scripts/simulate.py --days 300   # прогон 300 дней на синтетике
```

Ключ для локального запуска:

```bash
export ALPHAVANTAGE_KEY=ваш_ключ     # Linux / macOS
$env:ALPHAVANTAGE_KEY="ваш_ключ"     # Windows PowerShell
```

`scripts/simulate.py` прогоняет ту же самую функцию, что и GitHub Actions,
300 раз подряд на синтетическом рынке без всякой сети — и после каждого дня
проверяет, что деньги не теряются: капитал равен вложенному плюс реализованный
плюс нереализованный результат, с точностью до копейки, кэш не уходит в минус,
дубли не появляются, лимит по секторам держится. Долгий прогон можно резать на
части: `--max-seconds 150` останавливает его аккуратно и печатает команду для
продолжения с `--resume`.

Результат прогона на 300 днях (120 синтетических бумаг, seed 42): 253 закрытые
сделки, лестница заполнилась до 21 позиции, средний срок удержания 22.0 бара,
все инварианты выдержаны в каждый из 300 дней. Модуль обучения за это время
один раз отказался тюнить веса (было 39 сделок из нужных 40) и трижды откатил
предложение, не подтвердившееся вне обучающей выборки — то есть защита от
переобучения срабатывает, а не просто присутствует в коде.

Цифры доходности из этого прогона намеренно не привожу: рынок синтетический и
устроен так, чтобы в нём *был* находимый сигнал — иначе тест «находит ли
скоринг хорошие бумаги» ничего не проверяет. Это тест механики учёта и
исполнения, а не прогноз доходности.

## Структура

```
config.yml                  все настройки; веса правит робот
screener/
  pipeline.py               оркестрация: daily / weekly / monthly / report
  universe.py               состав S&P 500 (Wikipedia + локальный снимок)
  data/prices.py            дневные цены пакетом, с резервами
  data/fundamentals.py      недельные снимки, point-in-time чтение
  data/alpha_vantage.py     подтверждение кандидата, учёт квоты
  factors.py                RSI, моментум, скользящие средние
  scoring.py                фильтры, z-оценки, итоговый скор
  portfolio.py              лестница, исполнение по next open, учёт
  learn.py                  IC, подбор весов, откат
  excel_report.py           сборка Portfolio.xlsx
  benchmark.py              кривая SPY для сравнения
state/                      состояние портфеля (коммитится в git)
scripts/simulate.py         прогон 300 дней офлайн
tests/                      20 тестов + синтетический рынок
```

Почему состояние лежит в git: каждый торговый день — это отдельный коммит с
понятным диффом. Видно, что именно робот купил, почему и как изменился
капитал. Кэш цен (`state/cache/prices.csv.gz`) в `.gitignore`, иначе репозиторий
рос бы на мегабайты в день.

## Честные оговорки

Их стоит прочитать, прежде чем делать из результатов выводы.

**Systematic bias по выжившим.** Состав индекса берётся текущий. На торговлю
вперёд это не влияет никак, но исторический анализ внутри модуля обучения чуть
оптимистичен: компании, вылетевшие из индекса, в нём не участвуют.

**Резервный список тикеров неполный.** Основной источник состава индекса —
Wikipedia, оттуда приходят все ~503 бумаги, и снимок обновляется на каждом
запуске. Но встроенный аварийный список (`screener/data/sp500.csv`) содержит
только 145 крупнейших имён по всем 11 секторам — он собран без доступа к сети
и нужен лишь для того, чтобы робот не падал, если Wikipedia недоступна.
В такой день скрин пройдёт по 145 бумагам вместо 500. После первого удачного
запуска файл перезапишется полным составом, и проблема исчезнет сама.

**Point-in-time история копится с нуля.** Механизм датированных снимков
правильный, но в первые месяцы истории почти нет, и обучение опирается на
короткий ряд. Через год данные станут содержательными. Именно поэтому
обучение не включается, пока не наберётся 40 закрытых сделок.

**Проскальзывание — модель, а не факт.** 5 б.п. в каждую сторону — разумная
оценка для ликвидных бумаг S&P 500, но в реальности на открытии спред шире, и
для менее ликвидных имён издержки будут выше.

**Концентрация.** 21 позиция — это немного. Лимит в 7 позиций на сектор
ограничивает перекос, но портфель всё равно куда концентрированнее индекса, и
просадки будут заметно глубже.

**Качество бесплатных данных.** `yfinance` — неофициальный источник. Бывают
пропуски, случаются кривые значения. Робот проверяет цены через Alpha Vantage
и отбрасывает кандидата при расхождении больше 8%, но полностью это не
страхует.

**Расписание может выключиться само.** GitHub отключает scheduled workflows
после 60 дней без активности в репозитории. Робот коммитит каждый день, так
что при работающем `daily` проблемы нет — но если он надолго упадёт, включите
расписание обратно вручную.

**Это не инвестиционная рекомендация.** Бумажная торговля на исторических
данных. Прошлые результаты ничего не говорят о будущих.
